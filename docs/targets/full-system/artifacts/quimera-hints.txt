LIMIT BREAK AMM SECURITY AUDIT HINTS

== Architecture ==
Diamond proxy pattern. Core AMM at slot 0x9A1D delegates to modules (ModuleLiquidity, ModuleAdmin, ModuleFeeCollection). Pool types are pluggable via ILimitBreakAMMPoolType. Three pool types: Fixed (height-based), Dynamic (tick-based concentrated liquidity), SingleProvider (single LP with hook-sourced pricing).

== Known Finding ==
CP-006: CLOBHelper double-rounding (Medium). The CLOB transfer handler rounds fees twice — once in the helper and once in the core — extracting ~1 wei per swap. Accumulated over many swaps = economic drain.

== Key Invariants to Break ==
INV-S01: Token balance solvency — contractBalance >= sum(owed_to_LPs + owed_to_traders + pending_fees)
INV-S02: No value creation — sum(tokens_in) >= sum(tokens_out) across all ops in a tx
INV-SW02: No profitable round-trip — swap(A->B) then swap(B->A) must lose to fees
INV-SW03: Rounding favors protocol — rounding errors always benefit the pool, never the trader

== Fee Architecture ==
- Pool fee (poolFeeBPS): 0-10000 BPS. Charged on swaps.
- Protocol fee (protocolFeeBPS): percentage of pool fee taken as protocol revenue.
- Exchange fee (BPSFeeWithRecipient): external fee charged on top.
- FeeOnTop (FlatFeeWithRecipient): flat fee, NOT signed in permit SWAP_TYPEHASH.

== Known Intentional Asymmetries ==
- 100% fee (poolFeeBPS=10000): allowed on input swaps, rejected on output swaps.
- feeOnTop field NOT signed in permit — intentional design, not a bug.
- Transient storage for direct swap input not cleared after use (HOOK-001) — accepted by team.

== FixedPool Math ==
Height-based liquidity with packed ratio pricing. Key functions:
- FixedHelper._calculateInputLPAndProtocolFee: mulDivRoundingUp(amountIn, poolFeeBPS, MAX_BPS)
- FixedHelper._calculateOutputLPAndProtocolFee: mulDivRoundingUp(reserveAmountIn, poolFeeBPS, MAX_BPS - poolFeeBPS)
- FixedHelper.computeSwapStep: ratio-based swap with height traversal
- FixedHelper._splitAmountsAndFeesByHeight: distributes amounts across liquidity heights

Pool type addresses must have 6 leading zero bytes.
swapExtraData must be exactly 32 bytes (silently uses defaults otherwise).

== Rejected Submission Patterns (do NOT repeat these) ==
- Claiming feeOnTop is a vulnerability (it's intentional unsigned field)
- Claiming transient storage not cleared is exploitable (accepted by team)
- Claiming 100% fee asymmetry is a bug (intentional)
- Submissions without demonstrable economic impact (always show profit > 0 with Forge PoC)
